# EevntStore の作り方

（ストリーミングをベースにした暫定版）

art::v1::TStremingEventStore (TStreamingEventStoreV1.h など)をベースに使うことで簡略化しようとする試み。
FileSinkHeader と独自のデータ構造を持つ RAYRAW の出力ファイルを解析するためのクラスを作成する。オンラインにも同時に対応したいので、継承によるファイルの作成を試みるもの。（これ自体は TRIDFEventStore なども使えたか。）

公開されているメソッドのうち、Open をそのまま使うことでオンラインに対応する。一方で、GetTimeFrame, GetSubTimeFrame, GetHeartBeatFrame については変更が必要。GetTimeFrame ですべてを処理してしまえばよいか。
Process についても読み解く必要がある。

## art::v1::TStremingEventStore

nestdaq の 2024 年頃？の v1 ヘッダーが使用されたころのデータに対応したイベントストアで、現在は zmq を用いたオンラインモニターにも対応している。

### Init

- ファイルリストの取得
- segmented data のアップデート。新しく作るか、すでにある segmented データを使うか。現状では segmented data の名前が同じ場合は追加するような仕様になっているので、ファイルを同じ名前の segmented データがある場合でも、２つ同時に開いても大丈夫。異なる名前を使えばセグメントも分けられるし、その結果、マップも分けられる。（同じ IP アドレスを持つ異なるFEE が違うファイルに書いてあれば、同時に解析はできる。）
- ランヘッダーも上記同様に共有するか、独自のものを作るか決められる。
- イベントヘッダー名の衝突は許さないので、各 EventStore ごとに準備する必要がある。
- StartFrame の番号で イベントヘッダを初期化。

## PreProcess
- TStreamingModuleDecoderFactory::Clear を呼び出して、データを初期化する。
- セグメントデータも初期化する。

## Process

- フレーム番号のチェック（開始フレームと最大フレーム）
- データソースがあるかどうかチェック。あれば、GetHeartBeatFrame を呼び出す。
  - フレームがあればイベント番号を増やして、なければイベントを終了
- コンパイル時に ZMQ が有効で、パラメータでオンライン解析が有効になっていたら、ZMQ の接続をためしてイベントを抜ける
- データソースを確認してあれば削除
- Open を呼び出して、失敗したらランを終了、成功したらイベントを抜けて次の処理。

GetHeartBeatFrame ですべてを処理してしまえば良さそう。

## Open

- データソースがあるかどうか。あるのに呼ばれたらエラー。
- ファイルリストの最初から開けるものを探し出す。見つかったらそのファイル名を記憶。どのファイルも使えなかったらfalse を返却。
- TFileDataSource としてデータソースを準備。開ければ OK。（これは起こらないはず。）
- データソースからFileSinkHeaer を読み出して、ヘッダから情報を得る。
